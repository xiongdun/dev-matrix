## 二、Agent Operation System 核心差距分析

### 什么是 Agent Operation System？

Agent Operation System (AOS) 是一个**完整的 Agent 生命周期管理平台**，不仅仅是"多个 Agent 协作"，而是：

1. **Agent 能自主运行**，不需要人一直盯着
2. **Agent 之间能通信协作**，不只是串行流水线
3. **Agent 有完整的生命周期管理**（创建→运行→监控→重启→销毁）
4. **Agent 有可观测性**（日志、追踪、成本、性能）
5. **Agent 能从反馈中学习**，持续改进
6. **Agent 能安全地访问外部资源**（MCP、API、数据库）

### 差距矩阵

| 维度 | 当前状态 | AOS 目标 | 差距 |
|------|----------|----------|------|
| **Agent 自主性** | 被动等待人工触发 | 能自主感知事件并响应 | 🔴 大 |
| **Agent 间通信** | 串行流水线，无直接通信 | 支持消息总线、共享状态 | 🔴 大 |
| **生命周期管理** | 无 | 创建→运行→暂停→恢复→销毁 | 🔴 大 |
| **可观测性** | 基础日志 | 追踪、指标、成本、性能 | 🟡 中 |
| **工具生态** | 5 个内置工具 | MCP + 自定义工具 + 工具市场 | 🟡 中 |
| **记忆与学习** | 静态文件记忆 | 从反馈中学习、记忆衰减、知识图谱 | 🟡 中 |
| **安全沙盒** | 无 | Agent 级别权限隔离 + 沙盒执行 | 🔴 大 |
| **多模态** | 纯文本 | 图片/音频/视频/代码 | 🟡 中 |
| **部署与扩展** | 单机手动 | 容器化 + 自动扩缩容 | 🔴 大 |
| **人机协作** | 简单审批 | 智能路由、渐进式信任 | 🟡 中 |

## 三、P0 — Agent 自主性（核心差距）

### 3.1 事件驱动架构

**现状**：Agent 只能通过人工在工作台发消息触发。

**目标**：Agent 能感知外部事件并自主响应。

```
GitHub Webhook → Agent 感知 PR 创建 → 自动代码审查
文件变更 → Agent 感知代码修改 → 自动运行测试
定时触发 → Agent 自动执行巡检任务
```

**需求**：
- [ ] 事件总线增强：支持外部事件源（GitHub Webhook、文件监控、定时器）
- [ ] Agent 事件订阅：每个 Agent 声明自己关心的事件类型
- [ ] 事件→Agent 路由：事件自动路由到对应的 Agent
- [ ] 自主决策：Agent 可以决定是否响应事件（不是所有事件都需要处理）

### 3.2 后台自主运行

**现状**：Agent 只在用户发消息时运行一次。

**目标**：Agent 可以在后台持续运行，自主完成长周期任务。

**需求**：
- [ ] Agent 运行时：支持 Agent 在后台持续运行（不只是单次调用）
- [ ] 任务队列：Agent 从队列中获取任务，自主安排执行顺序
- [ ] 心跳机制：Agent 定期汇报状态，超时自动重启
- [ ] 资源限制：每个 Agent 有 token 预算、时间限制、并发控制

## 四、P0 — Agent 间通信

### 4.1 消息总线

**现状**：Agent 之间通过工作流串行传递状态，无直接通信。

**目标**：Agent 之间可以发送消息、共享上下文。

```
Developer Agent → "代码已生成，需要审查" → CodeReviewer Agent
QA Agent → "测试失败，问题在 auth.py:42" → Developer Agent
```

**需求**：
- [ ] Agent 消息协议：定义 Agent 间消息格式（request/response/notification）
- [ ] 共享上下文池：Agent 可以读写共享的上下文数据
- [ ] 消息路由：根据 Agent 角色自动路由消息
- [ ] 消息持久化：消息历史可追溯

### 4.2 协作模式

**现状**：只有串行流水线模式。

**目标**：支持多种协作模式。

| 模式 | 说明 | 场景 |
|------|------|------|
| **串行** | A → B → C | 标准开发流程 |
| **并行** | A + B + C 同时运行 | 多维度分析 |
| **投票** | 多个 Agent 投票决定 | 代码审查共识 |
| **辩论** | Agent 之间讨论达成共识 | 架构决策 |
| **委托** | Agent 将子任务委托给其他 Agent | 复杂任务分解 |

## 五、P1 — Agent 生命周期管理

### 5.1 Agent 注册与发现

**现状**：Agent 硬编码在 `app/agents/` 目录。

**目标**：动态注册、发现、管理 Agent。

**需求**：
- [ ] Agent 注册表增强：支持动态注册/注销 Agent
- [ ] Agent 元数据：每个 Agent 声明自己的能力、工具、触发条件
- [ ] Agent 健康检查：定期检查 Agent 是否可用
- [ ] Agent 版本管理：支持 Agent 升级和回滚

### 5.2 Agent 运行时管理

**需求**：
- [ ] Agent 启动/暂停/恢复/销毁
- [ ] Agent 运行状态监控（运行中/暂停/错误/空闲）
- [ ] Agent 资源使用监控（token 消耗、API 调用次数、执行时间）
- [ ] Agent 自动重启（崩溃后自动恢复）

### 5.3 Agent 配置管理

**需求**：
- [ ] Agent 级别配置：每个 Agent 可以有自己的 LLM 模型、温度、max_tokens
- [ ] Agent 级别权限：每个 Agent 可以访问的工具、文件、API 不同
- [ ] Agent 级别记忆：每个 Agent 有自己的记忆空间（已有 `_shared/`）

## 七、P1 — 工具生态

### 7.1 MCP 集成增强

**现状**：MCP 配置文件已支持，但未实际集成到 Agent 运行时。

**需求**：
- [ ] MCP 服务器自动发现和连接
- [ ] MCP 工具注册到 Agent 工具列表
- [ ] MCP 工具调用结果注入到对话上下文
- [ ] MCP 服务器健康监控

### 7.2 自定义工具

**需求**：
- [ ] 工具定义格式：用户可以通过 YAML/Markdown 定义自定义工具
- [ ] 工具沙盒：自定义工具在沙盒中运行，限制文件系统和网络访问
- [ ] 工具版本管理：工具升级和回滚
- [ ] 工具市场：社区共享的工具库

### 7.3 工具链

**需求**：
- [ ] 工具组合：多个工具串联执行（读取文件 → 分析 → 修改 → 测试）
- [ ] 工具条件执行：根据条件选择不同的工具
- [ ] 工具回滚：工具执行失败时自动回滚

## 八、P2 — 记忆与学习

### 8.1 从反馈中学习

**现状**：记忆系统是静态的文件，不会自动学习。

**需求**：
- [ ] 审批反馈学习：用户审批/打回 → Agent 记录原因，下次避免
- [ ] 纠正学习：用户修改 AI 输出 → Agent 学习正确的做法
- [ ] 成功模式提取：自动识别高评分输出的共同模式
- [ ] 失败模式识别：自动识别被拒绝输出的共同问题

### 8.2 知识图谱

**需求**：
- [ ] 代码知识图谱：函数调用关系、依赖关系、影响分析
- [ ] 项目知识图谱：需求→设计→代码→测试的映射关系
- [ ] 团队知识图谱：谁负责什么模块、谁审查过什么代码

### 8.3 记忆管理

**需求**：
- [ ] 记忆衰减：旧记忆自动降低权重
- [ ] 记忆冲突解决：新旧记忆冲突时的合并策略
- [ ] 记忆压缩：长对话自动摘要，保留关键信息
- [ ] 记忆隔离：不同项目的记忆互不干扰

## 九、P2 — 安全沙盒

### 9.1 Agent 权限隔离

**现状**：所有 Agent 共享相同的文件系统和工具权限。

**需求**：
- [ ] Agent 级别文件权限：每个 Agent 只能访问指定目录
- [ ] Agent 级别工具权限：每个 Agent 只能使用指定工具
- [ ] Agent 级别网络权限：每个 Agent 只能访问指定 API
- [ ] 权限审计：记录 Agent 的所有权限使用

### 9.2 沙盒执行

**需求**：
- [ ] Docker 沙盒：Agent 的 Bash 命令在 Docker 容器中执行
- [ ] 文件系统隔离：每个任务有独立的工作目录
- [ ] 网络隔离：限制 Agent 的网络访问
- [ ] 资源限制：CPU、内存、磁盘、网络带宽

## 十一、P3 — 人机协作增强

### 11.1 智能路由

**现状**：用户手动选择 SDK 和 Agent。

**目标**：系统根据任务类型自动选择最合适的 Agent 和 SDK。

**需求**：
- [ ] 任务分类器：自动识别任务类型（需求分析/代码生成/审查/测试）
- [ ] Agent 能力匹配：根据任务类型选择最合适的 Agent
- [ ] SDK 智能选择：根据任务复杂度选择最合适的 SDK

### 11.2 渐进式信任

**需求**：
- [ ] 信任等级：新 Agent 默认需要人工审批，成熟后可以自动执行
- [ ] 风险评估：自动评估 Agent 输出的风险等级
- [ ] 自动审批：低风险操作自动审批，高风险操作人工审批

### 11.3 协作界面

**需求**：
- [ ] Agent 思维过程可视化：展示 Agent 的推理过程
- [ ] 实时干预：用户可以在 Agent 执行过程中插入指令
- [ ] 分支对话：用户可以创建多个对话分支比较不同方案
